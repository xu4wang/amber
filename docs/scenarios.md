# 主要场景的实现方式

每个场景都按同一个顺序讲：**跟 agent 怎么说**、**应用里要声明什么**（这些都写在应用定义里，随代码一起审核）、**用的时候要注意什么**。脚本具体怎么写由 agent 负责，技术细节见[脚本约定](script.md)。

## 1. 查数据出报表（按执行人自己的权限）

> 查一下近 7 天每个城市的注册商户数，做成表格和柱状图。……存进 Amber，叫「注册商户数」，天数做成参数。

- **声明**：调用数据服务 `data-mcp`，并写明每次执行最多调用几次（比如 `calls: 1`）。
- **身份**：每次执行，Amber 给数据服务签发一张代表**执行人本人**的短时效凭证，数据服务按这个人的权限返回数据。同一个应用，不同的人执行，看到的是各自有权限的数据。agent 和脚本都改不了这个身份。
- **注意**
  - 声明了数据服务的应用**不能访问外网**，查到的数据传不出去。
  - agent 不能直接执行这类应用，总要你本人在确认卡上点一下；**结果只显示在卡片上**，不会交给 agent。
  - 输出里的表格、图表会显示成飞书表格和图表（卡片里每张表最多 100 行，完整内容在网站上看）。
  - 试运行最多返回 20 行。

## 2. 定时监控，有异常才提醒

> 每 15 分钟检查一下今天的失败交易数，超过 100 笔就提醒我，正常的时候别发消息。

- **声明**：允许定时执行（默认就是允许的）。
- **关键写法**：**正常时什么都不输出，有异常才输出**。Amber 的规则是脚本没有输出就不发消息，所以正常时不会打扰任何人。
- 建好应用后，再对 agent 说「每 15 分钟跑一下」，在确认卡上点「创建定时任务」。
- **注意**
  - 定时任务每次都以**创建人**的身份运行，结果发到原来的群或话题。
  - 失败时只私聊通知创建人；连续失败 3 次自动暂停。
  - 应用下线、出了新版本（需要你点「换绑」）、创建人退群时，定时任务都会自动暂停。

## 3. 需要外部系统的 token、密码

> 调 GitLab 接口查一下这个仓库昨天有没有新提交。……存进 Amber，GitLab 的 token 做成密钥。

- **声明**：密钥的**名字**（比如 `GITLAB_TOKEN`）。代码里只写名字，从不写值。要访问外部系统的，还要声明「可以访问外网」。
- **填值**：认领时在认领卡上点「设置密钥」，Amber 私聊你一张卡片填写；以后在网站应用页的「密钥」里改。**不要把 token 发给 agent，也不要贴在群里。**
- **注意**
  - 值加密保存，只交给这个应用，设置后谁都看不到原值（只显示末尾 4 位）。
  - 脚本如果把密钥原样打印出来，结果里会自动遮成 `***`。
  - 用到密钥的应用，agent 不能直接执行，总要你本人点确认卡。
  - 应用只有你能执行，所以密钥只有你自己在用；设为全局的应用例外，所有执行人共用一份。

## 4. 访问机器人在本机建的数据（比如台账）

> 读一下你维护的客户台账，列出这周要回访的客户。……存进 Amber。

机器人自己的数据（台账、导出文件等）在它所在的机器上，不在 Amber 那台机器上。做法是：

- **前提**：那台机器上装好了**执行端**，管理员批准了一个**运行环境**。从 botmux 机器人导出的环境，能访问的数据和这个机器人在自己沙箱里能访问的一样。这一步由部署方和管理员完成，见[执行端与运行环境](executor.md)。
- **声明**：应用写明在哪个环境里运行（`env: "执行端名/环境名"`）。代码里**不写任何路径声明**，能访问什么完全由环境决定。agent 用 `amber envs --mine` 找到属于自己的环境。
- **注意**
  - 应用在那台机器上、那个环境的沙箱里执行；没有写环境的应用在 Amber 本机跑，看不到任何业务数据。
  - 这类应用**不能上架到 Store**，也**不能设为全局**；要给同事用，用[复制给群成员](sharing.md#1-复制给同群的人克隆)。
  - 执行端离线时执行会直接失败，提示执行端不在线。

## 5. 把结果交给群里的机器人或同事

> 每天早上检查一下仓库，有新提交就 @同步机器人 让它拉最新代码；没有就什么都不说。

- **写法**：脚本输出的正文里写 `@名字`，名字要和对方在群里的显示名完全一样，比如 `仓库有 3 个新提交。@同步机器人 请拉取最新代码并重新部署。`
- **效果**：正式运行时，Amber 发结果卡时把它换成真正的 @。被 @ 的人会收到提醒，被 @ 的机器人（比如 botmux 的机器人）会被唤起，接着处理。
- **注意**
  - 不用另外声明；审核时看代码就知道它会 @ 谁。
  - 只在群里的正式运行生效（手动执行、agent 发起后由人确认的执行、定时任务）；试运行和私聊只显示文字。
  - 名字后面要空一格，或者接标点、换行：`@张三 请看` 会 @，`@张三请看` 不会。
  - `@所有人` 不生效；群里有同名的人、对方不在群里时不 @。一次最多 @ 5 个人。表格和图表里的 @ 不生效。
  - 机器人看到的发送者是 Amber，不是任何人，所以需要人员身份的操作它做不了。要它做的事在正文里写清楚。

## 6. 把结果写进飞书文档

> 把这周的回访名单写进一个飞书文档，发我链接。……存进 Amber。

- **做法**：应用在一个从 botmux 机器人导出的运行环境里运行（见场景 4），脚本里调用 `lark-cli`，用的是**这个机器人的飞书身份**，和它平时在会话里用的一样。
- **声明**：运行环境，以及「可以访问外网」（lark-cli 要访问飞书接口）。
- **注意**
  - 文档的创建人是那个机器人。机器人建的文档默认只有它自己能看，需要在脚本里把你加成协作者，或者让机器人分享给你。
  - 一个应用里「访问外网」和「调用数据服务」只能二选一（为了防止查到的数据被传出去）。所以「用 data-mcp 查数再写进飞书文档」要拆成两个应用，或者在机器人自己的会话里完成。

## 7. 每次都一样的值

> 检查的仓库地址每次都一样，做成配置项，不要每次让人填。

- **声明**：这个参数标成配置项（`scope: "config"`）。
- **设置**：应用生效后，在网站上这个应用页面底部的「配置项」里设置一次，以后每次执行（包括定时任务）自动带上，执行的人改不了。必填的配置项没设置时不能执行。
- **注意**：配置项不保密，看得到这个应用的人都能看到值；token、密码要用密钥。试运行时还没有地方保存，配置项在试运行表单里填，只用于这次试运行。

## 8. 给同事用

应用默认只有你自己能看见、能执行。给同事用有四种方式：复制给同群的人、上架到 Amber Store、管理员设为全局、离职交接时管理员重新分配。区别和怎么选见[应用的分享](sharing.md)。
