# 应用的分享

在 Amber 里，一个应用默认**只有创建它的人自己看得见、能执行**，群里的其他人看不到。这样每个应用都有明确的负责人，密钥和配置项也不会被别人拿去用。

想让别人也用上，有四种方式：

| 方式 | 一句话 | 谁来做 |
|---|---|---|
| [复制给同群的人](#1-复制给同群的人克隆) | 把自己的应用复制一份送给同群的某个人，送完各管各的 | 应用的创建人 |
| [上架到 Amber Store](#2-上架到-amber-store) | 审核一次后放进 Store，谁都可以装自己的一份，之后还能升级 | 应用的创建人申请，审核人审批 |
| [设为全局应用](#3-全局应用) | 所有人在所有地方都能直接用这一个应用，共用一份设置 | 管理员 |
| [重新分配](#4-重新分配退群人员的应用) | 创建人离开了群，把他的应用整个交给群里的另一个人 | 管理员 |

不管用哪种方式，有几件事是一样的：

- **执行身份永远是执行的那个人。** 应用调用数据服务（比如查数据）时，按执行人自己的权限返回。
- **代码都是审核过的那一份。** 这四种方式都不用重新审核代码：复制、安装、全局化、重新分配用的都是已经审核通过的版本。
- **要对方本人同意的地方，都要对方在飞书上点一下。** 复制和重新分配，都要接收的人自己点「接收」，因为以后是以他的身份执行。

## 1. 复制给同群的人（克隆）

把自己的一个群应用复制一份，送给同一个群里的某个人。对方接收后，那一份就是**他自己的、独立的应用**，和你的那份不再有任何关系。

**怎么做**

1. 在网站上打开自己的应用，页面底部「复制给群成员」里选一个人，点「发送」。
2. 对方在飞书上收到确认卡，可以改个名字，点「接收」。确认卡 7 天内有效。
3. 接收后，对方在这个群里 @Amber 发应用名就能执行。

**复制什么、不复制什么**

| 内容 | 是否复制 | 说明 |
|---|---|---|
| 代码、参数、选项 | 复制 | 就是审核过的那一份 |
| 执行环境（`env`） | 复制 | 在执行端环境里运行的应用，副本也在原来的环境里运行 |
| 配置项的值 | 复制 | 配置项不保密，复制过去当起点，对方可以自己改 |
| 密钥 | **不复制** | 那是你的凭证。对方要在网站上填自己的，填好之前不能执行 |
| 定时任务 | 不复制 | 对方需要的话自己建 |

**之后**：两份完全独立。对方可以自己提交新版本（照常审核）、下线；你的应用出新版本，对方的那份不会跟着变，反过来也一样。

**限制**

- 只有应用的创建人能发起（管理员也不行），只能给**同一个群**的成员。
- 从 Store 装来的应用不能复制，对方可以自己去 Store 装。
- 同一个群里，对方自己的应用不能重名，重名时在确认卡上改个名字即可。

**适合**：给身边一两个同事用；在执行端环境里运行的应用（这类应用暂时不能上架，复制是目前唯一的分享办法）。

## 2. 上架到 Amber Store

把应用上架到 Amber Store，任何人都可以在网站上**安装自己的一份**。安装不用审批，装好的那份以安装人的身份执行，配置项和密钥各填各的。和复制不同，上架后**原来的应用（原版）出新版本时，装了的人可以升级**。

**上架**（创建人）

1. 在网站上打开自己的应用，页面底部「Amber Store」里点「申请上架」。
2. 审核人在飞书审批里审核一次（标题「Amber 上架」）。除了平常的审核，还会看代码里有没有写死只适用于某个群或某个人的内容，这类内容要先改成配置项。
3. 通过后，你的这个应用就是这个 Store 应用的「原版」，照常使用，标「已上架」。

**安装**（任何人）

1. 网站左边「Amber Store」里选一个应用，可以看说明、要填什么、需要哪些配置项和密钥、能做什么、代码和审核文档。
2. 选装到哪里（你所在、并且 Amber 也在的群，或你和 Amber 的私聊），起个名字，点「安装」。
3. 在装好的应用页面里填配置项和密钥（你自己的），就可以用了。

**升级**：原版提交新版本、审核通过后，它就是 Store 里的新版本，装了的人收到私聊通知。**不会自动升级**：在网站上看完改动后自己点「升级」，配置项、密钥、定时任务都会跟过去。

**下架**：维护人（原版的创建人）或管理员可以下架。下架后不能再新装，已经装好的照常可用；需要时可以重新上架。原版下线时，可以选择让应用留在 Store（不再更新）或者同时下架；之后维护人或管理员可以用「开发模式安装」装一份当新的原版，接着开发。

**限制**：在执行端环境里运行的应用（写了 `env`）暂时不能上架，因为环境绑定在某台机器、某个机器人上，装到别处用不了；从 Store 装来的应用也不能再上架。

**适合**：通用的工具，多个群、很多人都要用，而且希望以后能统一升级。网站上的操作见[网站操作](web.md#amber-store)。

## 3. 全局应用

管理员可以把一个应用**设为全局**：Amber 所在的任何群、任何人的私聊、网站上，所有人都能直接看到和执行**这一个应用**。不用复制，也不用安装。

**怎么做**：管理员在飞书里对 Amber 说「全局 应用名」，或者让 agent 发起、管理员在确认卡上点确认。取消也一样（「取消全局 应用名」）。不需要重新审核。

**和其他方式最大的区别：设置是共用的。** 全局应用只有一份密钥、一份配置项，由创建人（或管理员）设置，**所有执行人都用这一份**。所以用到密钥时，看到的是这个凭证的权限，不是执行人自己的权限；结果卡上会标「使用全局应用共用的密钥」。调用数据服务时仍然按执行人自己的权限。

**之后**：创建人仍然是负责人，由他改设置、提交新版本（新版本自动保持全局）、下线。

**限制**

- 只有管理员能设。全局应用之间不能重名；某个地方有同名的本地应用时，以本地的为准。
- 在执行端环境里运行的应用（写了 `env`）**不能设为全局**，否则任何人都能在那个机器人的环境里执行、访问它能访问的数据。

**适合**：少数确实需要所有人共用一份设置、而且不涉及个人凭证的应用，比如查天气、查汇率这类公共工具。一般的分享建议用 Store，每人一份、设置各管各的。

## 4. 重新分配（退群人员的应用）

创建人离开了群（比如离职），他在这个群里的应用就没人能执行了：只有创建人能执行，而他已经不在群里。管理员可以把这样的应用**整个交给**群里的另一个人。

**怎么做**

1. 管理员在网站上能看到标着「创建人已离群」的应用，打开后在页面底部「重新分配」里选一个群成员，点「发送确认卡」。
2. 对方在飞书上收到确认卡，选择：
   - **接收，并重建定时任务**：原来的定时任务以他的身份重建，时间、参数不变；
   - **只接收应用**：原来的定时任务删除；
   - **不接收**。
3. 接收后，他就是这个应用的创建人。发起的管理员会收到通知。

**和复制的区别**：重新分配不会多出一个应用，而是**同一个应用换了负责人**。所以原来的配置项和**密钥都保留**（多数是离职交接，凭证要接着用），新负责人可以在网站上修改；以后的新版本也是在这个应用上继续。

**限制**

- 只对创建人已不在群里的应用；只能交给群成员。创建人还在群里时，管理员不能把他的应用转走。
- 接收时会再查一遍：原创建人回群了、应用在这期间更新或下线了、已经有别人接收了，都不会生效。确认卡 7 天内有效，管理员重新发起时旧卡作废。
- 原来因为创建人离群而暂停的定时任务，重建后照常运行；手动暂停或因连续失败暂停的，重建后仍然暂停。

**适合**：人员离职、调岗后的交接。

## 对比

| | 复制给同群的人 | 上架到 Store | 全局应用 | 重新分配 |
|---|---|---|---|---|
| 谁发起 | 应用的创建人 | 创建人申请，审核人审批 | 管理员 | 管理员 |
| 给谁 | 同群的某一个人 | 任何人（自己去装） | 所有人 | 同群的某一个人 |
| 要不要审批 | 不用 | 上架时审核一次，安装不用 | 不用 | 不用 |
| 对方要不要确认 | 要（点「接收」） | 安装就是本人操作 | 不用 | 要（点「接收」） |
| 结果 | 多出一个对方自己的应用 | 每人装一个自己的应用 | 还是这一个应用，大家共用 | 还是这一个应用，换了负责人 |
| 执行身份 | 执行人自己 | 执行人自己 | 执行人自己 | 执行人自己 |
| 密钥 | 各填各的（不复制） | 各填各的 | **共用一份** | 保留原来的 |
| 配置项 | 复制过去，之后各改各的 | 各填各的 | **共用一份** | 保留原来的 |
| 定时任务 | 不复制 | 各建各的 | 各建各的 | 可选择以新负责人身份重建 |
| 原应用出新版本 | 不受影响 | 收到通知，自己决定升级 | 直接就是新版本 | 新负责人自己提交 |
| 在执行端环境里运行的应用 | **可以** | 暂时不行 | **不行** | 可以 |
| 和原应用的关系 | 断开，各管各的 | 保持（可升级） | 就是原应用 | 就是原应用 |

## 怎么选

- **给身边一两个同事用一下**，或者应用在执行端环境里运行：**复制给同群的人**。
- **很多人、很多群都要用的通用工具**，希望以后统一升级：**上架到 Store**。
- **所有人都要用、而且必须共用同一份设置**（例如一个公共账号查公开数据）：请管理员**设为全局**。涉及个人凭证的不要这样做。
- **同事离职或调岗**，他的应用还要继续用：请管理员**重新分配**。

## 常见问题

**复制给别人后，我改了自己的应用，对方的会变吗？**
不会。复制出去的那份是对方独立的应用。需要对方也用上你的改动，可以再复制一份给他（他接收时换个名字，或者先把旧的下线）；或者干脆把应用上架到 Store，让大家通过升级拿到新版本。

**同一个群里有好几个人各有一个同名应用，agent 再提交这个名字算谁的？**
按认领人算：提交时带上认领人（agent 的 skill 里要求带上），就是认领人自己那个应用的新版本；认领人在这个群里还没有这个名字的应用时，就是一个新应用。没带认领人、又有好几个同名应用时，Amber 会拒绝，请 agent 带上认领人再提交。

**管理员能直接执行别人的应用吗？**
不能。管理员可以看到所有应用，查看代码、设置配置项和密钥、下线、管理定时任务（暂停、恢复、删除）、重新分配，但不能执行别人的应用，也不能替别人认领新版本。需要用的话，按上面的方式让创建人分享给你。
