# 管理员手册

管理员负责应用**上线之后**的管理。名单由部署方写在 Amber 配置里（`admins`）。管理员和审核人是两种独立的角色：审核人决定代码能不能上线，管理员不能跳过审核让应用生效；同一个人可以兼任。

## 能做什么、不能做什么

| | 创建人 | 管理员 |
|---|---|---|
| 看到应用 | 自己的 | **所有人的**（网站上所有群的应用，包括自己不在的群） |
| 执行应用、试运行、立即运行定时任务 | 自己的 | **只能是自己的**，不能执行别人的应用 |
| 认领新版本 | 自己应用的 | 也只能是自己应用的（认领了就成了创建人，会用上原创建人的密钥和配置项） |
| 设置配置项和密钥 | 自己的 | 任何应用 |
| 下线应用 | 自己的 | 任何应用 |
| 设为全局 / 取消全局 | — | 可以 |
| 重新分配 | — | 创建人已不在群里的应用 |
| 定时任务 | 自己的：暂停、恢复、删除、立即运行 | 任何人的：暂停、恢复、删除（不能立即运行别人的） |
| Amber Store | 维护人：下架、重新上架、开发模式安装 | 下架、重新上架、开发模式安装、更换维护人 |
| 执行端 | — | 批准、拒绝、撤销 |

一句话：**管理员能看、能管、能停，但不能替别人执行**。需要用别人的应用，请对方用复制或上架的方式分享给你。

## 在飞书里

| 发什么 | 做什么 |
|---|---|
| `所有应用` | 列出所有生效中的应用（id、名字、范围） |
| `全局 应用名`、`取消全局 应用名` | 设为全局 / 改回只在创建处可用。有重名时改用 id |
| `下线 应用名` | 下线任何应用（确认卡 5 分钟内有效） |
| `执行端` | 列出执行端和在线状态 |
| `撤销执行端 名称` | 立即撤销一个执行端 |

## 全局应用

全局应用在 Amber 所在的任何群、任何人的私聊和网站上，所有人都能直接执行。设成全局不需要重新审核。

- **密钥和配置项所有执行人共用一份**，所以用到密钥时，看到的是这个凭证的权限，不是执行人自己的权限。结果卡上会标「使用全局应用共用的密钥」。
- 在执行端环境里运行的应用**不能设为全局**，否则任何人都能在那个机器人的环境里执行。
- 建议只把少数确实需要所有人共用一份设置、不涉及个人凭证的应用设为全局；一般的分享用 Store。

详细对比见[应用的分享](sharing.md)。

## 重新分配（离职、退群的交接）

创建人离开了群，他在这个群里的应用就没人能执行了。

1. 网站上会给这类应用标「创建人已离群」。打开后在页面底部「重新分配」里选一个群成员，点「发送确认卡」。
2. 对方在飞书上选「接收，并重建定时任务」「只接收应用」或「不接收」。接收后对方就是创建人，你会收到通知。
3. 配置项和密钥保留；原来因为创建人离群而暂停的定时任务，重建后照常运行。

只有创建人已不在群里的应用能重新分配；创建人还在群里时，管理员不能把他的应用转走。

## 定时任务

在网站上能看到所有人的定时任务，可以暂停、恢复、删除，但不能「立即运行」别人的（那等于执行别人的应用）。暂停只会让任务停下，发现问题时可以先暂停再联系创建人。

## Amber Store

- **下架**：不能再新装，已经装好的照常可用，原版的新版本也不再进入 Store。
- **重新上架**：版本都审核过，不再审批。
- **更换维护人**：在应用页面填新维护人的邮箱。维护人可以下架、重新上架，原版下线后可以用开发模式安装接着开发。
- **开发模式安装**：原版下线后，把应用装进一个群作为新的原版，安装人成为维护人。

## 执行端

执行端装在数据所在的机器上，让应用在那台机器的运行环境里执行（比如读机器人的台账）。安装方法见[执行端与运行环境](executor.md)。

- **批准登记**：执行端申请登记时，每位管理员会收到一张卡片，上面有来源机器、每个环境开放的全部路径（含凭证的路径标红）和**公钥指纹**。**先和安装的人核对指纹一致**，再看路径是否合理，然后批准或拒绝。批准前不会派任何任务。
- **变化通知**：环境里路径、环境变量、Python 的改动直接生效，你会收到变化通知卡（新增的凭证路径标红），卡上可以直接撤销。新增环境、改了工作目录等要重新批准。
- **撤销**：飞书里发「撤销执行端 名称」，或在通知卡、网站上撤销。立即停止派任务；已经启动的脚本会跑到结束或超时（最长 120 秒）。要恢复，得在那台机器上重新生成密钥再申请。
- **网站**：左侧「执行端（管理员）」里能看每个执行端的状态、是否在线、环境路径和公钥指纹，并批准、拒绝或撤销。

## 审计

认领、审核、执行、下线、全局化、重新分配、复制、上架、安装、密钥和配置项的修改、执行端的批准和撤销等操作都会写进审计记录。审计记录保存在 Amber 的数据库里（`audit` 表），目前网站上没有审计页面，需要时请部署方查询。
