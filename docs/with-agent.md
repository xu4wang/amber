# 和自己的 agent 协作

日常使用时，你只需要跟自己的 agent 说话，agent 在底层调用 Amber。下面每一项都给出可以直接照抄的说法。

agent 替你发起的事，凡是要**以你的身份**做的（执行要用你权限的应用、建定时任务、下线等），Amber 都会发一张确认卡，你本人点了才生效。agent 没法向 Amber 证明它在替谁做事，所以这一步替不了。

## 应用

| 想做的事 | 对 agent 说 | 之后 |
|---|---|---|
| 新建应用 | 先把事情跑通，再说：「**把刚才这个存进 Amber，叫『注册商户数』，天数做成参数**」 | 认领卡上试运行 → 提交审核，等全部审核人同意 |
| 修改应用 | 在**原来的群或私聊**里说：「**把『注册商户数』改成按城市分组，用同一个名字提交新版本**」 | 认领卡标「新版本」并列出代码差异；只有原创建人能认领；审核通过前线上一直是旧版本 |
| 执行 | 「**帮我跑一下注册商户数，最近 30 天**」 | 见下面的「执行时会发生什么」 |
| 看有哪些应用 | 「**这里有哪些 Amber 应用**」 | agent 列出你自己的应用和全局应用 |
| 下线 | 「**下线应用 注册商户数**」 | 确认卡上点「确认下线」。不需要审核，不能撤销 |

几点说明：

- **应用名就是应用的身份。** 同一个名字提交是新版本，换个名字就是另一个新应用。Amber 没有「改名」，旧名字的应用要单独下线。
- 同一个群里几个人各有一个同名应用时（比如复制来的），Amber 按认领人判断是谁那个的新版本，agent 提交时会带上你。
- 新版本审核通过后，挂在旧版本上的定时任务先暂停，Amber 私聊你一张换绑卡，点一下就继续运行。

## 执行时会发生什么

| 应用的情况 | agent 怎么做 | 结果给谁看 |
|---|---|---|
| 不需要身份：不调用数据服务、也没开「执行前确认」（比如查天气） | agent 直接执行，把结果告诉你 | agent 和你 |
| 需要身份：调用数据服务（按你的权限查数据）、开了「执行前确认」，或者用到密钥 | Amber 在当前对话里发一张**确认卡**，你点「执行」才执行 | **只显示在确认卡上**（完整内容在网站「最近运行」里），**不会交给 agent** |

为什么第二种不把结果给 agent：这是以你的身份查出来的数据，只给你看。agent 只知道执行完成了，想就结果继续问，请直接看卡片。

## 定时任务

| 想做的事 | 对 agent 说 | 之后 |
|---|---|---|
| 创建 | 「**每个工作日早上 9 点帮我跑一下注册商户数，天数 7**」 | 确认卡上点「创建定时任务」。点卡片的人就是定时任务的创建人，以后每次都以他的身份运行 |
| 查看 | 「**这里有哪些定时任务**」 | 只列你自己建的 |
| 暂停 | 「**暂停定时任务 注册商户数**」 | 立即生效，不用点卡片 |
| 恢复 | 「**恢复定时任务 注册商户数**」 | 确认卡上点确认 |
| 删除 | 「**删除定时任务 注册商户数**」 | 确认卡上点确认，删除后不能恢复 |
| 改时间或参数 | Amber 没有「修改定时任务」：先删除，再按新的时间和参数重新创建 | 各点一次确认卡 |

时间写法：`每天 09:00`、`工作日 18:30`、`每周一 08:45`、`每小时`、`每 2 小时`、`每 2 小时 15 分`、`每 15 分钟`（分钟间隔只能是 5、10、15、20、30，最短 5 分钟）。时间按 Amber 配置的时区计算，确认卡上会写明。

**脚本没有输出时不发消息**，所以「有异常才提醒」这类监控，正常时不会打扰你。失败时只私聊通知创建人，连续失败 3 次自动暂停。

## agent 做不了、要你自己来的事

| 事情 | 在哪里做 |
|---|---|
| 认领、试运行、提交审核 | 认领卡上 |
| 审核 | 飞书审批（审核人） |
| 填密钥 | 私聊 Amber 发「设置密钥 应用名」，或在网站上 |
| 设置配置项 | 网站上的应用页面 |
| 登录网站 | 私聊 Amber 发「登录」 |
| 上架到 Store、安装、复制给同事 | 网站上，见[应用的分享](sharing.md) |

**不要把密钥发给 agent。** agent 提交需要密钥的应用时只写密钥的名字，值由你自己填。
