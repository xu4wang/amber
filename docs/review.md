# 审核指南

审核人决定一段代码能不能上线。应用都是 AI 写的代码，审核通过后代码就按哈希锁定，以后每次执行跑的都是你审过的这一份；代码有任何改动都要重新审核。

## 谁来审、怎么算通过

- 审核人名单由部署方写在 Amber 配置里（`reviewers`）。
- **所有审核人都同意**才算通过，少一个都不行；**任何一个人驳回**就是驳回。
- 审核在飞书「审批」里做。配置了飞书审批时，Amber 用会签审批，并在飞书知识库里建一篇审核文档；没配飞书审批时，审核人会在私聊里收到审核卡片，在卡片上通过或驳回（驳回要填原因）。

## 三种审核

| 审批标题 | 是什么 | 重点看 |
|---|---|---|
| Amber 应用：名称 | 新应用 | 全部内容 |
| Amber 应用：名称（新版本） | 已有应用的新版本 | 审核文档开头的「与当前版本的差异」。已上架到 Store 的应用，审核文档会注明「审核通过后会成为 Store 里的新版本」 |
| Amber 上架：名称 | 把一个已经在用的应用上架到 Amber Store | 平常的检查之外，看有没有写死只适用于某个群或某个人的内容（见下面「上架时额外看什么」） |

审核文档里有：应用说明、参数表（标出哪些是配置项）、选项、运行方式、使用的密钥、执行位置、完整代码，以及认领人试运行时的输出。审批单上也有一段摘要。

## 审什么

按下面的清单逐项看。审批单和审核文档里都写明了这些信息，不用自己去翻代码猜。

| 项目 | 看什么 |
|---|---|
| **做的事** | 代码做的事和说明一致；试运行的输出合理。只读的应用不应该有写操作 |
| **参数和配置项** | 参数含义清楚。配置项（每次执行自动带上、执行人改不了）里不应该放 token、密码这类机密，机密要用密钥 |
| **密钥** | 声明了哪些密钥、各用来做什么。代码只把密钥用在该用的地方：不打印、不写进文件、不发给无关的地址 |
| **联网** | 声明了「可以访问外网」的应用能访问任何地址，也就能把数据发出去。只在确实需要时才允许，并看代码访问的是哪些地址 |
| **数据服务** | 调用了哪些服务（比如 `data-mcp`）、每次执行最多调用几次。这类应用以执行人的身份查数据，不能同时访问外网（Amber 会强制），所以查到的数据传不出去 |
| **执行位置** | 写了运行环境的应用在某台机器的执行端上运行，能访问的路径由环境决定（审批单上会列出环境信息）。看代码只碰它需要的数据，有没有写入、删除文件 |
| **执行前确认** | 会改数据、有风险的操作，应该打开「执行前确认」，这样只能在表单上点红色按钮执行，不能一句话直接执行 |
| **允许定时** | 打开后，创建人可以让它按时间自动运行（以创建人身份）。会改数据的应用要慎重 |
| **解释器** | 指定了特定的 Python（为了用第三方包）时，看它是不是正常的路径 |
| **@ 谁** | 输出里写了 `@名字` 的，正式运行时会真正 @ 到群里的人或机器人；看会 @ 谁、交代了什么 |

## 上架时额外看什么

上架后，任何人都可以装自己的一份，安装不再审批。所以除了上面的清单，还要看：

- **有没有写死只适用于某个群或某个人的内容**，比如群名、某个人的名字、特定的仓库或账号。这些应该改成配置项，否则别人装了也用不了，或者会访问到不该访问的东西。
- 说明写得够不够清楚，别人看了知道要填哪些配置项、密钥。

在执行端环境里运行的应用不能上架，你不会收到这类上架审核。

## 常见风险

| 风险 | 怎么发现 |
|---|---|
| 把密钥打印出来或者发到别处 | 看密钥变量用在哪里（打印出来的会被遮成 `***`，但发往外部地址的拦不住） |
| 把查到的数据发到外部地址 | 声明了外网的应用，看所有网络请求的目标 |
| 名义上只读，实际会改数据 | 看 SQL、接口调用的类型；会改数据的要打开「执行前确认」 |
| 在执行环境里读写超出需要的文件 | 看文件路径，特别是遍历目录、删除文件的代码 |
| 写死了人或群 | 上架审核时特别注意，应该改成配置项 |

## 驳回之后

驳回时写清楚原因（卡片审核必须填原因；飞书审批里写在审批意见里）。认领卡会显示「未通过」和原因，认领人可以让 agent 改好后用同一个名字重新提交，再走一遍审核。

审核通过后，如果发现应用有问题，创建人或管理员可以随时下线它，下线不需要审核。
