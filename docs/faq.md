# 常见问题

## 基本概念

**为什么要认领和审核？**
应用是 AI 写的代码，可能会改数据，也可能会访问外部系统。认领确保有人对它负责；审核确保有人看过代码。审核通过后代码就锁定了，以后每次执行跑的都是同一份代码。

**群里建的应用，群里其他人能用吗？**
不能。应用只有创建人自己看得见、能执行，群里其他人看不到，管理员也只能查看、不能执行。要给别人用，见[应用的分享](sharing.md)。全局应用除外，所有人都能用。

**执行时用的是谁的身份？**
总是「执行的那个人」：在飞书里发消息或点卡片的人；agent 发起的，就是点确认卡的人；定时任务是创建定时任务的人。查数据时，你能看到的就是你本人有权限看的数据。

**为什么有时要点确认卡，有时不用？**
agent 没法向 Amber 证明它在替谁做事，所以需要身份的应用必须由你本人点一下。规则是固定的：应用**调用了数据服务**、**开了「执行前确认」**、或者**用到密钥**，就要确认卡；都没有的（比如查天气），agent 可以直接执行。这几项写在应用定义里，随代码一起审核，agent 改不了。

**数据服务拿到的身份可信吗？**
可信。身份只来自飞书（发消息、点卡片或网站登录的那个人）。Amber 每次执行给数据服务签发一张短时效的签名凭证，服务方用 Amber 的公钥验签，就能确认「是谁、在执行哪个审核过的应用」；agent、脚本、请求内容都改不了。声明了数据服务的脚本不能访问外网，查到的数据传不出去。服务方怎么接入见[可信身份](identity.md)。

## 应用

**应用想改怎么办？要重新审核吗？**
要，和新建应用走一样的流程（认领、试运行、审核）。跟 agent 说要改什么，它会用同一个名字提交新版本。认领卡和审核文档会标「新版本」并列出代码差异。新版本只有原创建人能认领（管理员也不行）。审核通过前，线上一直跑旧版本；通过后自动替换。挂在旧版本上的定时任务会先暂停，Amber 私聊创建人一张卡片，点「换绑到新版本」就继续运行。

**怎么下线？要审核吗？**
不用审核：下线只会减少能力，发现问题时要能马上停掉。只有创建人或管理员能下线，每次都写审计。对 agent 说「下线应用 应用名」后点确认卡，或者在网站应用页面底部点「下线这个应用」，或者在飞书里对 Amber 说「下线 应用名」。下线后不能再执行，定时任务暂停，配置项和密钥一起删除。

**能改应用的名字吗？**
不能。应用名就是应用的身份，换个名字提交就是另一个新应用，旧的要单独下线。

**我看不到某个群里的应用？**
网站和飞书里只显示你自己建的应用和全局应用，别人的看不到。如果是你自己建的、也确实在群里却看不到，请联系管理员确认 Amber 有读取群成员的权限。

**确认卡别人能点吗？**
agent 指明了替谁发起时（通常如此），只有这个人能点；没指明时，群里谁点都可以，谁点就以谁的身份执行，所以不是你发起的请求不要点。

## 参数、配置项和密钥

**有些参数每次都一样，能不能不用每次填？**
用配置项，见[主要场景](scenarios.md)里的「每次都一样的值」。改配置项的值不需要重新审核；增加或删除配置项要提交新版本。

**应用需要 token、密码怎么办？**
用密钥，见[主要场景](scenarios.md)里的「需要外部系统的 token、密码」。能防的是别的应用、agent、群里其他人、其他进程读到明文；防不了的是审核时没看出来的恶意代码，所以审核时要留意代码怎么使用密钥。

## 定时任务

**按哪个时区？**
按 Amber 配置的默认时区，确认卡和网站上会写成「每天 09:00（北京时间）」这样。网站上创建时可以从下拉框选别的时区。

**创建人退群或离职了，定时任务怎么办？**
到下一次该运行时，Amber 发现创建人已不在群里，会暂停这个定时任务并私聊通知创建人。定时任务不能直接「转给」别人（那等于把一个人的数据权限换成另一个人的）；需要的话，管理员可以把应用重新分配给群里的另一个人，对方接收时可以选择以自己的身份重建这些定时任务。

**注意有最长约 10 分钟的延迟**：Amber 判断「是否在群里」用的群成员名单会缓存 10 分钟。所以创建人退群后的最多 10 分钟内，定时任务可能还会按他的身份照常跑一到两轮。退群前想让任务立刻停，先把它**暂停**（立即生效）。

## 网站

**能在群里登录网站吗？**
能。在群里 @Amber 发「登录」，登录卡片会发到你和 Amber 的私聊里，链接不会出现在群里。

**怀疑别人用了我的登录？**
在飞书私聊 Amber 发「退出网站」，所有浏览器里的登录都会失效。

## 其他

**管理员和审核人有什么区别？**
审核人决定代码能不能上线，管理员负责上线之后的管理。管理员不能跳过审核，也不能执行别人的应用；审核人也不能下线别人的应用。见[审核指南](review.md)和[管理员手册](admin.md)。

**应用要读机器人建的台账怎么办？**
用执行端和运行环境，见[主要场景](scenarios.md)里的「访问机器人在本机建的数据」。

**部署文档里有两处安装，按哪个？**
它们装的不是同一个东西。[安装与部署](install.md)是部署 Amber 服务端，一个组织只部署一套；[agent 接入](cli-and-skill.md)是在每台跑 agent 的机器上装客户端。只想让自己的 agent 用上 Amber，看后者就够了。
