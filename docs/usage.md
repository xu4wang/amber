# 使用指南

Amber 能把你和 AI 助手（agent）一起跑通的一次操作，固化成一条**指令**。以后随时一键执行，执行时不再经过 AI，每次结果都可预期。

本文写给使用 Amber 的人，不需要任何技术背景。想先看操作演示，可以看[视频手册](https://xu4wang.github.io/amber-manual/)，按章节观看，每章 1 分钟左右。

## 1. 几个概念

| 概念 | 说明 |
|---|---|
| 指令 | 一段审核过的脚本，加上它需要的参数，比如「天气」带一个「城市」参数。指令只能由审核通过的那一版代码执行，代码一改就要重新审核 |
| 范围 | 指令属于创建它的群或私聊。群指令只有群成员能用，私聊指令只有你自己能用。管理员可以把指令设为「全局」，让所有地方都能用 |
| 定时任务 | 让一条指令按时间自动执行，比如「工作日 09:00」。每次都以创建人的身份执行 |
| 执行身份 | 指令总是以「点按钮的那个人」的身份执行。查数据时，你能看到的就是你本人有权限看的数据 |

### 创建人、管理员、审核人

三种角色互相独立：管理员不一定是审核人，审核人也不一定是管理员；同一个人可以兼任。管理员和审核人名单由部署方写在 Amber 配置里。

| | 创建人 | 管理员 | 审核人 |
|---|---|---|---|
| 是谁 | 认领指令的人（定时任务则是创建它的人） | 配置里的 `admins` | 配置里的 `reviewers` |
| 让指令上线 | — | 不能单独决定 | **全部审核人都在飞书审批里同意**，指令才生效；少一个人同意都不行 |
| 认领新版本 | 只能认领自己指令的新版本 | 可以认领任何指令的新版本 | — |
| 下线指令 | 自己的指令 | 任何指令 | — |
| 全局 / 本地 | — | 在飞书里对 Amber 说「全局 指令名」「取消全局 指令名」，「所有指令」查看全部 | — |
| 管理定时任务 | 自己创建的（暂停、恢复、删除、立即运行） | 任何定时任务 | — |

简单说：**审核人决定代码能不能上线，管理员负责上线之后的管理**。管理员不能跳过审核让指令生效，审核人也不能下线别人的指令。

## 2. 把一次操作固化成指令

1. 在飞书里和你的 agent 把事情做成，比如「查一下近 7 天的注册商户数并画图」。
2. 对 agent 说：「**把刚才这个存进 Amber，叫『注册商户数』**」。可以顺便说明哪些地方要做成参数，比如「天数可以改」，以及要不要允许定时执行。
3. Amber 会在当前的群或私聊里发一张**认领卡**。认领卡上有代码和说明：
   - 点「**试运行**」，Amber 会以你的身份真实执行一次。有参数的话，先在卡片上填好。
   - 结果没问题就点「**提交审核**」。认领的人就是这条指令的创建人。
   - 不认识、不需要的草稿，直接点「**丢弃**」。
4. 审核人会在飞书「审批」里收到待办，在飞书知识库里能看到完整代码和试运行结果。**所有审核人都同意**后，指令生效，认领卡也会变成「已生效」。

## 3. 执行指令

### 在飞书里

- 私聊 Amber，或者在群里 @Amber，发「**帮助**」，会列出这里能用的指令，点「选择」后填参数执行。
- 直接发指令名和参数也可以，比如「天气 上海」。
- 结果会直接更新在卡片上：表格显示成表格，折线图和柱状图显示成飞书图表。
- 标着「**需确认**」的指令会改数据或有风险，一定要从表单里点红色的「确认执行」才会执行。

### 让 agent 帮你执行

直接跟你的 agent 说「帮我跑一下注册商户数，最近 30 天」：

- 不涉及个人权限的指令，agent 会直接执行，再把结果告诉你。
- 需要用你的身份，或者需要确认的指令，Amber 会在当前对话里发一张**确认卡片**。你点「执行」之后才会执行，结果同时显示在卡片上和 agent 的回复里。
- agent 指明了被请求人时（通常如此），只有这个人能点，别人点会被拒绝。agent 没有指明时，群里谁点都可以，**谁点就以谁的身份执行**，所以不是你发起的请求不要点。

### 在网站上

1. 登录：在群里 @Amber 发「**登录**」（或直接私聊 Amber 发），Amber 会把登录卡片发到你和 Amber 的**私聊**里，点卡片上的「打开 Amber 网站」。这个链接 5 分钟内有效、只能用一次，**不要转发给别人**。
2. 左边是指令树，按「我的私聊 / 各个群 / 全局指令」分组。选中一条指令后：
   - 「执行」页：填参数后执行，结果显示在下方。
   - 「定时」页：创建定时任务。只有允许定时的指令才有这一页。
   - 「代码」页：查看审核通过、实际在运行的代码、第几版和历史版本，以及审核文档链接。
   - 页面底部的「管理」：你是创建人（或管理员）时，可以在这里下线指令。
3. 「最近运行」里有你在所有渠道（飞书、网站、agent、定时）的执行记录，可以随时回看输出。
4. 不用时点右上角「退出」。如果怀疑别人用了你的登录，在飞书私聊 Amber 发「**退出网站**」，所有浏览器里的登录都会失效。

## 4. 定时任务

- 只有审核时允许定时的指令才能定时执行。
- 两种创建方式：在网站上指令的「定时」页填写；或者对 agent 说「每个工作日早上 9 点帮我跑一下注册商户数」，然后点它发来的确认卡片。
- 时间写法：

| 写法 | 例子 |
|---|---|
| 每天、工作日、每周几的固定时间 | 每天 09:00、工作日 18:30、每周一 08:45 |
| 每隔几小时 | 每小时、每 2 小时、每 2 小时 15 分 |
| 每隔几分钟（最短 5 分钟） | 每 5 分钟、每 15 分钟、每 30 分钟 |

- 时间按 Amber 服务器设定的时区计算，可以选的时区以网站上的下拉框为准。确认卡片和网站上都会写明是哪个时区。
- 结果发到飞书：群指令发到原来的群或话题，私聊和全局指令发到你和 Amber 的私聊。**脚本没有输出时不发消息**，所以「有异常才提醒」这类监控，正常时就不会打扰你。
- 失败时只私聊通知创建人。连续失败 3 次会自动暂停。指令下线、换了新版本、你退出了那个群时，定时任务也会自动暂停。因为创建人退群而暂停时，Amber 还会在群里发一张提醒卡，群成员都可以点「由我接手」：之后以接手人的身份（按他自己的数据权限）继续运行，参数和时间不变；没人接手就一直暂停。
- 在网站上可以暂停、恢复、立即运行一次或删除自己的定时任务。在飞书里 @Amber 发「定时任务」也能看到列表。

## 5. 常见问题

**为什么要认领和审核？**
指令是 AI 写的代码，可能会改数据，也可能会访问外部系统。认领确保有人对它负责；审核确保有人看过代码。审核通过后代码就锁定了，以后每次执行跑的都是同一份代码。

**群里建的指令，群里其他人能用吗？用谁的身份？**
能。群指令所有群成员都能看到、都能执行，而且总是以「执行的那个人」的身份执行：在群里 @Amber 用卡片执行，就是发消息或点卡片的人；agent 发起的，就是点确认卡片的人。所以同一条查数据的指令，不同的人执行，看到的是各自有权限的数据。

**为什么有时要点确认卡片，有时不用？怎么判断一条指令需不需要身份？**
agent 没法向 Amber 证明它是在替谁做事，所以需要身份的指令必须由你本人在飞书里点一下。判断规则是固定的，不靠人或 agent 判断：指令**声明了要调用的服务**（比如查数仓），或者**开了「执行前确认」**，就需要身份；两条都不满足的（比如查天气），agent 可以直接执行，执行身份记为 agent。这两项写在指令定义里，随代码一起审核，agent 改不了。

**确认卡片别人能点吗？**
agent 指明了是替谁发起的（通常如此），就只有这个人能点，别人点会被拒绝。agent 没有指明时，群里谁点都可以，谁点就以谁的身份执行，所以不是你发起的请求不要点。

**卡片上写的「你的 agent」是谁？**
是帮你提交或发起请求的 AI 助手。agent 没报名字时就显示「你的 agent」。

**我看不到某个群里的指令？**
网站只显示你所在群的指令。如果你确实在群里却看不到，请联系管理员确认 Amber 有读取群成员的权限。

**指令想改怎么办？改版本要审核吗？**
要，和新建指令走完全一样的流程（认领、试运行、飞书审批、所有审核人同意）。审核通过之前，线上一直跑旧版本。跟 agent 说要改什么，它会用同一个名字提交新版本。认领卡和审核文档里会标明「新版本」，并列出和当前版本的代码差异。新版本只能由原创建人（或管理员）认领，审核通过后自动替换旧版本。挂在旧版本上的定时任务会先暂停，Amber 私聊创建人一张卡片，点「换绑到新版本」就会继续运行，参数和时间都不变。

**不需要的指令怎么下线？下线要审核吗？**
不需要审核：下线只会减少能力，发现指令有问题时要能马上停掉。但只有创建人或管理员能下线，每次都写审计。创建人或管理员可以在网站上指令页面底部点「下线这条指令」，或者在飞书里对 Amber 说「下线 指令名」，Amber 会回一张确认卡，发起人本人在 5 分钟内点「确认下线」才生效。下线后不能再执行，它的定时任务会暂停并通知创建人。

**定时任务按哪个时区？**
按 Amber 服务器配置的默认时区（dev-beta 上是北京时间），确认卡片和网站上都会写成「每天 09:00（北京时间）」这样。网站上创建时可以从下拉框选其他时区。

**定时任务的创建人退群或离职了怎么办？**
到下一次该运行时，Amber 发现创建人已不在群里，会暂停这个定时任务，私聊通知创建人，并在群里发一张提醒卡。群成员都可以点「由我接手」：之后以接手人的身份（按他的数据权限）继续运行，参数和时间不变。没人接手就一直暂停。定时任务不能直接「转给」别人，因为那等于把一个人的数据权限换成另一个人的，必须由接手的人自己点。

**能在群里登录网站吗？**
能。在群里 @Amber 发「登录」，Amber 会把登录卡片发到你和 Amber 的私聊里，链接不会出现在群里。

**管理员和审核人有什么区别？**
审核人决定代码能不能上线，管理员负责上线之后的管理（全局/本地、下线任何指令、管理任何定时任务）。管理员不能跳过审核。详见上面的[创建人、管理员、审核人](#创建人管理员审核人)。

**部署文档里有两处安装命令，按哪个？**
它们装的不是同一个东西。[安装与部署](install.md) 是部署 Amber 服务端，一个组织只部署一套（dev-beta 上已经有了）；[amber 命令行与 skill](cli-and-skill.md) 是在每台跑 agent 的机器上装客户端。只是想让自己的 agent 用上 Amber，看后者就够了。
