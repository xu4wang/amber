# 使用指南

Amber 能把你和 AI 助手（agent）一起跑通的一次操作，固化成一条**指令**。以后随时一键执行，执行时不再经过 AI，每次结果都可预期。

本文写给使用 Amber 的人，不需要任何技术背景。想先看操作演示，可以看[视频手册](https://xu4wang.github.io/amber-manual/)，按章节观看，每章 1 分钟左右。

## 1. 几个概念

| 概念 | 说明 |
|---|---|
| 指令 | 一段审核过的脚本，加上它需要的参数，比如「天气」带一个「城市」参数。指令只能由审核通过的那一版代码执行，代码一改就要重新审核 |
| 范围 | 指令属于创建它的人，建在哪个群或私聊就在哪里用：**只有创建人自己看得见、能执行**，群里其他人看不到。别人要用，等它上架 Amber Store 后安装自己的一份（Store 还在开发中）。管理员可以看到所有指令（查看代码、设置、下线），但不能执行别人的指令；管理员把指令设为「全局」后，所有人在所有地方都能用。结果卡、定时任务的报告照样发在群里 |
| 定时任务 | 让一条指令按时间自动执行，比如「工作日 09:00」。每次都以创建人的身份执行 |
| 执行身份 | 指令总是以「点按钮的那个人」的身份执行。查数据时，你能看到的就是你本人有权限看的数据 |
| 配置项 | 不用每次执行都填的参数，比如要检查的仓库、通知的机器人。**名字和类型**随代码一起审核；**值**由创建人或管理员在网站上设置一次，以后每次执行（包括定时任务）都自动带上，执行的人不能临时改。值不保密，看得到这条指令的人都能看到 |
| 密钥 | 指令运行时需要的凭证，比如某个系统的 API token、服务账号密码，相当于部署生产系统时配置的环境变量。**名字**随代码一起审核；**值**由创建人或管理员在私聊或网站上填写，加密保存，只交给这条指令，设置后谁都不能再查看 |

### 创建人、管理员、审核人

三种角色互相独立：管理员不一定是审核人，审核人也不一定是管理员；同一个人可以兼任。管理员和审核人名单由部署方写在 Amber 配置里。

| | 创建人 | 管理员 | 审核人 |
|---|---|---|---|
| 是谁 | 认领指令的人（定时任务则是创建它的人） | 配置里的 `admins` | 配置里的 `reviewers` |
| 让指令上线 | — | 不能单独决定 | **全部审核人都在飞书审批里同意**，指令才生效；少一个人同意都不行 |
| 认领新版本 | 只能认领自己指令的新版本 | 可以认领任何指令的新版本 | — |
| 下线指令 | 自己的指令 | 任何指令 | — |
| 全局 / 本地 | — | 对 agent 说「把 指令名 设为全局 / 取消全局」后点确认卡；或在飞书里对 Amber 说「全局 指令名」「取消全局 指令名」，「所有指令」查看全部 | — |
| 管理定时任务 | 自己创建的（暂停、恢复、删除、立即运行） | 任何定时任务的暂停、恢复、删除（不能立即运行别人的） | — |

简单说：**审核人决定代码能不能上线，管理员负责上线之后的管理**。管理员不能跳过审核让指令生效，审核人也不能下线别人的指令。

## 2. 把一次操作固化成指令

1. 在飞书里和你的 agent 把事情做成，比如「查一下近 7 天的注册商户数并画图」。
2. 对 agent 说：「**把刚才这个存进 Amber，叫『注册商户数』**」。可以顺便说明哪些地方要做成参数，比如「天数可以改」。指令**默认允许定时执行**，不需要的话跟 agent 说「不要定时」。
   - 指令名就是指令的身份：以后用**同一个名字**提交就是新版本；换个名字就是另一条新指令（Amber 没有「改名」，旧指令需要单独下线）。
3. Amber 会在当前的群或私聊里发一张**认领卡**（在话题里提交的就回到这个话题，并 @ 让 agent 固化的人）。认领卡上有代码和说明：
   - 点「**试运行**」，Amber 会以你的身份真实执行一次。有参数的话，先在卡片上填好。
   - 结果没问题就点「**提交审核**」。认领的人就是这条指令的创建人。
   - 不认识、不需要的草稿，直接点「**丢弃**」。
4. 审核人会在飞书「审批」里收到待办，在飞书知识库里能看到完整代码和试运行结果。**所有审核人都同意**后，指令生效，认领卡也会变成「已生效」。

## 3. 执行指令

### 在飞书里

- 私聊 Amber，或者在群里 @Amber，发「**帮助**」，会列出这里能用的指令，点「选择」后填参数执行。
- 直接发指令名和参数也可以，比如「天气 上海」。
- 结果会直接更新在卡片上：表格显示成表格（卡片里每张表最多 100 行，完整内容在网站上看），折线图、柱状图、饼图显示成飞书图表，并标出数值。
- 标着「**需确认**」的指令会改数据或有风险，一定要从表单里点红色的「确认执行」才会执行。

### 让 agent 帮你执行

直接跟你的 agent 说「帮我跑一下注册商户数，最近 30 天」：

- 不涉及个人权限的指令，agent 会直接执行，再把结果告诉你。
- 需要用你的身份，或者需要确认的指令，Amber 会在当前对话里发一张**确认卡片**。你点「执行」之后才会执行，**结果只显示在这张卡片上**（完整内容在网站「最近运行」里），**不会交给 agent**：这是以你的身份查出来的数据，只给你看。agent 只知道执行完成了，所以想就结果继续问，请直接看卡片。
- agent 指明了被请求人时（通常如此），只有这个人能点，别人点会被拒绝。agent 没有指明时，群里谁点都可以，**谁点就以谁的身份执行**，所以不是你发起的请求不要点。

### 在网站上

1. 登录：在群里 @Amber 发「**登录**」（或直接私聊 Amber 发），Amber 会把登录卡片发到你和 Amber 的**私聊**里，点卡片上的「打开 Amber 网站」。这个链接 5 分钟内有效、只能用一次，**不要转发给别人**。
2. 左边是指令树，按「我的私聊 / 各个群 / 全局指令」分组。选中一条指令后：
   - 「执行」页：填参数后执行，结果显示在下方。
   - 「定时」页：创建定时任务。审核时没有允许定时的指令，这一页会说明原因和开启方法。
   - 「代码」页：查看审核通过、实际在运行的代码、第几版和历史版本，以及审核文档链接。
   - 页面底部的「配置项」：有配置项的指令会列出每一项的当前值；你是创建人（或管理员）时，可以在这里设置或清除。配置项只能在网站上设置，飞书里没有入口。
   - 页面底部的「密钥」：需要密钥的指令会列出密钥名字和是否已设置；你是创建人（或管理员）时，可以在这里填写、覆盖或删除（只显示末尾 4 位，看不到原值）。
   - 页面底部的「管理」：你是创建人（或管理员）时，可以在这里下线指令。
   - 结果里的图表在网站上也会标出数值：折线和柱状图标在每个点、每根柱子上，饼图用引导线标出「类别，占比 / 数值」。
3. 「最近运行」里有你在所有渠道（飞书、网站、agent、定时）的执行记录，可以随时回看输出。
4. 不用时点右上角「退出」。如果怀疑别人用了你的登录，在飞书私聊 Amber 发「**退出网站**」，所有浏览器里的登录都会失效。

## 4. 定时任务

- 只有审核时允许定时的指令才能定时执行（新提交的指令默认允许）。
- 两种创建方式：在网站上指令的「定时」页填写；或者对 agent 说「每个工作日早上 9 点帮我跑一下注册商户数」，然后点它发来的确认卡片。
- 时间写法：

| 写法 | 例子 |
|---|---|
| 每天、工作日、每周几的固定时间 | 每天 09:00、工作日 18:30、每周一 08:45 |
| 每隔几小时 | 每小时、每 2 小时、每 2 小时 15 分 |
| 每隔几分钟（最短 5 分钟） | 每 5 分钟、每 15 分钟、每 30 分钟 |

- 时间按 Amber 服务器设定的时区计算，可以选的时区以网站上的下拉框为准。确认卡片和网站上都会写明是哪个时区。
- 结果发到飞书：群指令发到原来的群或话题，私聊和全局指令发到你和 Amber 的私聊。**脚本没有输出时不发消息**，所以「有异常才提醒」这类监控，正常时就不会打扰你。
- 结果里可以 @ 群里的人或机器人，把事情交给对方继续处理，见下面的「在结果里 @ 人或机器人」。
- 失败时只私聊通知创建人。连续失败 3 次会自动暂停。指令下线、换了新版本、你退出了那个群时，定时任务也会自动暂停（退群的判断有最长约 10 分钟延迟，见下面的问答）。指令只有创建人能执行，所以别人不能接手。
- 在网站上可以暂停、恢复、立即运行一次或删除自己的定时任务。在飞书里 @Amber 发「定时任务」也能看到列表。

### 在结果里 @ 人或机器人

脚本输出的正文里写 `@名字`，名字和本群某个成员（人或机器人）在群里的显示名完全一样时，Amber 发结果卡时会把它换成真正的 @。被 @ 的人会收到提醒，被 @ 的机器人（比如 botmux 的机器人）会被唤起，接着处理。例如每天检查代码仓库，有更新时输出：

```
仓库有 3 个新提交。@同步机器人 请拉取最新代码并重新部署。
```

- 指令不用另外声明，审核时看代码就能知道它会 @ 谁。
- 只在群里的正式运行生效：手动执行、agent 发起后由人确认的执行、定时任务。试运行和私聊只显示文字。
- 名字后面要空一格，或者接标点、换行：`@张三 请看`、`@张三，请看` 会 @，`@张三请看` 不会（Amber 分不清名字在哪里结束）。
- `@所有人` 不生效；群里有两个同名成员、对方不在群里、写的不是完整的名字时都不 @，只显示文字。群太大（超过 5000 人）、Amber 取不全成员列表时也不 @。
- 一次运行最多 @ 5 个不同的成员。表格（` ```table `）和图表里的 @ 不生效。
- 机器人看到的发送者是 Amber，不是任何人，所以需要人员身份的操作它做不了。把要它做的事在正文里写清楚。

## 5. 操作速查

**所有操作都跟你的 agent 说就行**，由 agent 在底层调用 Amber。下面每一项都给出可以直接照抄的说法。Amber 只在两个地方出现：一是它发出的**卡片**，凡是要以你的身份做的事（认领、执行、建定时、下线等）都要你本人点一下，这是身份安全的底线，agent 替不了；二是**登录网站**，登录链接只发在你和 Amber 的私聊里，所以要直接私聊 Amber 发「登录」。

### 指令

| 操作 | 怎么做 | 谁能做 | 要不要点卡片 |
|---|---|---|---|
| 新增 | 先和 agent 把事情跑通，再说：「**把刚才这个存进 Amber，叫『注册商户数』，天数做成参数**」。在认领卡上点「试运行」→「提交审核」，等全部审核人同意 | 任何人可以认领 | 要：认领卡上试运行、提交审核 |
| 修改 | 在**原来的群或私聊**里对 agent 说：「**把『注册商户数』改成按城市分组，用同一个名字提交新版本**」。认领卡会标「新版本」并列出代码差异，同样要试运行、审核 | 只有原创建人或管理员能认领新版本 | 要：和新增一样走认领和审核；审核通过前线上一直是旧版本 |
| 下线 | 对 agent 说：「**下线指令 注册商户数**」，然后在 Amber 发来的确认卡上点「确认下线」。也可以在网站指令页底部点「下线这条指令」 | 创建人或管理员 | 要：创建人或管理员点「确认下线」。不需要审核 |
| 设置密钥 | 私聊 Amber 发「**设置密钥 注册商户数**」，在 Amber 发来的卡片上填写；新指令在认领卡上点「设置密钥」，Amber 会私聊你填写。也可以在网站指令页的「密钥」一栏设置或删除 | 创建人或管理员；还没认领的新草稿：能认领它的人 | 不用确认卡，但**只能在你和 Amber 的私聊里填写** |
| 设为全局 / 取消全局 | 对 agent 说：「**把注册商户数设为全局**」或「**取消注册商户数的全局**」，然后在确认卡上点确认。全局指令在 Amber 所在的任何群和私聊都能用 | 管理员 | 要：管理员点确认 |

- 指令名就是指令的身份：用**同一个名字**提交是新版本；换个名字就是另一条新指令。Amber 没有「改名」，旧名字的指令要单独下线。
- 修改审核通过后，挂在旧版本上的定时任务会先暂停，Amber 私聊创建人一张卡片，点「**换绑到新版本**」就继续运行，时间和参数不变。
- 下线后指令不能再执行，它的定时任务会暂停并通知创建人；它的密钥也会一起删除。
- **不要把密钥发给 agent，也不要贴在群里**。agent 提交需要密钥的指令时只写密钥的名字，值由你在私聊卡片或网站上填写。

### 定时任务

| 操作 | 怎么做 | 谁能做 | 要不要点卡片 |
|---|---|---|---|
| 创建 | 对 agent 说：「**每个工作日早上 9 点帮我跑一下注册商户数，天数 7**」，然后点确认卡上的「创建定时任务」。也可以在网站指令页的「定时」页填写 | 能执行这条指令的人（指令的创建人；全局指令是所有人）；**点卡片的人就是定时任务的创建人**，以后都以他的身份运行 | 要 |
| 查看 | 对 agent 说：「**这里有哪些定时任务**」。网站上也有列表 | 每个人只看到自己建的；管理员在网站上能看到全部 | 不用 |
| 暂停 | 对 agent 说：「**暂停定时任务 注册商户数**」 | 创建人或管理员 | 不用，**立即生效** |
| 恢复 | 对 agent 说：「**恢复定时任务 注册商户数**」，然后在确认卡上点确认 | 创建人或管理员 | 要 |
| 删除（下线） | 对 agent 说：「**删除定时任务 注册商户数**」，然后在确认卡上点确认 | 创建人或管理员 | 要；删除后不能恢复 |
| 修改时间或参数 | **Amber 没有「修改定时任务」**。先删除，再按新的时间和参数重新创建 | 删除：创建人或管理员；重建：重建的人成为新的创建人 | 要（删除、创建各一次） |

- 在群里操作群指令、群定时任务的卡片，**必须在原来那个群里点**。
- 习惯直接找 Amber 也可以：私聊或在群里 @Amber 发「帮助」「定时任务」「下线 指令名」，效果一样。
- 退群判断有最长约 10 分钟延迟，见下面「常见问题」里的说明。退群前想让任务马上停，先「暂停」。

## 6. 常见问题

**为什么要认领和审核？**
指令是 AI 写的代码，可能会改数据，也可能会访问外部系统。认领确保有人对它负责；审核确保有人看过代码。审核通过后代码就锁定了，以后每次执行跑的都是同一份代码。

**群里建的指令，群里其他人能用吗？用谁的身份？**
不能。指令只有创建人自己看得见、能执行，群里其他人看不到，管理员也只能查看、不能执行。别人要用同样的功能，等它上架 Amber Store 后安装自己的一份，填自己的配置项和密钥（Store 还在开发中）；全局指令除外，所有人都能用。
指令总是以「执行的那个人」的身份执行：在群里 @Amber 用卡片执行，就是发消息或点卡片的人；agent 发起的，就是点确认卡片的人。全局指令被不同的人执行时，看到的是各自有权限的数据。

**为什么有时要点确认卡片，有时不用？怎么判断一条指令需不需要身份？**
agent 没法向 Amber 证明它是在替谁做事，所以需要身份的指令必须由你本人在飞书里点一下。判断规则是固定的，不靠人或 agent 判断：指令**声明了要调用的服务**（需要可信身份的后端服务，比如按你的权限查数据的服务），或者**开了「执行前确认」**，就需要身份；两条都不满足的（比如查天气），agent 可以直接执行，执行身份记为 agent。这两项写在指令定义里，随代码一起审核，agent 改不了。

**指令调用后端服务时，服务拿到的是谁的身份？可信吗？**
是执行人本人的身份（飞书 union_id），而且只来自飞书：发消息、点卡片或网站登录的那个人。Amber 每次执行都给声明的服务签发一张短时效的签名凭证，服务方用 Amber 的公钥验签，就能确认「是谁、在执行哪条审核过的指令」；agent、脚本、请求内容都改不了这个身份。所以同一条指令由不同的人执行，服务会按各自的权限返回。声明了服务的脚本不能访问外网，查到的数据无法外传。服务方怎么接入见[可信身份](identity.md)。

**确认卡片别人能点吗？**
agent 指明了是替谁发起的（通常如此），就只有这个人能点，别人点会被拒绝。agent 没有指明时，群里谁点都可以，谁点就以谁的身份执行，所以不是你发起的请求不要点。

**卡片上写的「你的 agent」是谁？**
是帮你提交或发起请求的 AI 助手。agent 没报名字时就显示「你的 agent」。

**我看不到某个群里的指令？**
网站只显示你自己建的指令（在你所在的群和你的私聊里）和全局指令，别人建的指令看不到。如果是你自己建的、你也确实在群里却看不到，请联系管理员确认 Amber 有读取群成员的权限。

**指令想改怎么办？改版本要审核吗？**
要，和新建指令走完全一样的流程（认领、试运行、飞书审批、所有审核人同意）。审核通过之前，线上一直跑旧版本。跟 agent 说要改什么，它会用同一个名字提交新版本。认领卡和审核文档里会标明「新版本」，并列出和当前版本的代码差异。新版本只能由原创建人（或管理员）认领，审核通过后自动替换旧版本。挂在旧版本上的定时任务会先暂停，Amber 私聊创建人一张卡片，点「换绑到新版本」就会继续运行，参数和时间都不变。

**不需要的指令怎么下线？下线要审核吗？**
不需要审核：下线只会减少能力，发现指令有问题时要能马上停掉。但只有创建人或管理员能下线，每次都写审计。最简单是对你的 agent 说「下线指令 指令名」，Amber 发来确认卡，创建人或管理员点「确认下线」才生效。也可以在网站指令页面底部点「下线这条指令」，或在飞书里对 Amber 说「下线 指令名」（这种方式的确认卡 5 分钟内有效）。下线后不能再执行，它的定时任务会暂停并通知创建人。

**定时任务按哪个时区？**
按 Amber 服务器配置的默认时区，确认卡片和网站上都会写成「每天 09:00（北京时间）」这样。网站上创建时可以从下拉框选其他时区。

**定时任务的创建人退群或离职了怎么办？**
到下一次该运行时，Amber 发现创建人已不在群里，会暂停这个定时任务，并私聊通知创建人。指令只有创建人能执行，所以别人不能接手；需要的话，等这条指令上架 Amber Store 后，由别人安装自己的一份、建自己的定时任务。定时任务也不能「转给」别人，因为那等于把一个人的数据权限换成另一个人的。

**注意有最长约 10 分钟的延迟**：Amber 判断「是否在群里」用的群成员名单会缓存 10 分钟，且不监听退群事件。所以创建人退群后的最多 10 分钟内，定时任务可能还会按他的身份（他的数据权限）照常跑一到两轮，结果照常发到群里；缓存过期后的下一轮才会暂停。退群前想让任务立刻停，请先把它**暂停**（暂停立即生效），不要让它处于运行状态时退群。

**能在群里登录网站吗？**
能。在群里 @Amber 发「登录」，Amber 会把登录卡片发到你和 Amber 的私聊里，链接不会出现在群里。

**管理员和审核人有什么区别？**
审核人决定代码能不能上线，管理员负责上线之后的管理（全局/本地、下线任何指令、管理任何定时任务）。管理员不能跳过审核。详见上面的[创建人、管理员、审核人](#创建人管理员审核人)。

**部署文档里有两处安装命令，按哪个？**
它们装的不是同一个东西。[安装与部署](install.md) 是部署 Amber 服务端，一个组织只部署一套，已经有了就不用再装；[amber 命令行与 skill](cli-and-skill.md) 是在每台跑 agent 的机器上装客户端。只是想让自己的 agent 用上 Amber，看后者就够了。

**指令要读本机的文件（比如机器人建的台账）怎么办？**
指令自己不写路径，能访问什么由**运行环境**决定：在数据所在的机器上装一个执行端，登记一个运行环境（一个目录，或者直接从 botmux 导出某个机器人的访问权限），管理员批准后，指令写明在哪个环境里跑就行。在从机器人导出的环境里，脚本能访问的数据和这个机器人在自己沙箱里能访问的一样，用 lark-cli 时也是这个机器人的身份。不写环境的指令在 Amber 本机跑，不访问任何业务数据。详见[执行端](executor.md)，开头的「概念」一节讲了机器、执行端、运行环境、沙箱的关系。

**有些参数每次都一样，能不能不用每次填？**
用配置项。让 agent 在草稿里给这个参数加上 `"scope": "config"`，审核时审核人能看到哪些是配置项。指令生效后，创建人或管理员在网站上这条指令页面底部的「配置项」里设置值。
- 执行时 Amber 把配置项的值和本次参数一起交给脚本；表单卡、网站执行页、agent 都不再要这些值，执行的人也改不了。
- 必填的配置项没设置（又没有默认值）时，执行和创建定时任务都会被拒绝，提示去网站设置。
- 改值不需要重新审核，下一次执行（包括定时任务）就用新值；增加或删除配置项需要提交新版本。
- 试运行时还没有地方保存值，配置项在试运行表单里填（标「配置项」），只用于这次试运行，不会保存。
- 指令下线时，它的配置项一起删除；同名的新版本审核通过后，沿用原来的值。
- 配置项不保密，看得到这条指令的人都能看到值。token、密码要用密钥。

**指令需要 token、密码怎么办？**
让 agent 在草稿里声明需要哪些密钥（只写名字，比如 `API_TOKEN`），审核时审核人能看到这条指令用了哪些密钥。值由创建人或管理员私聊 Amber 发「设置密钥 指令名」填写，或在网站上填写；新指令在认领卡上点「设置密钥」，填好后再试运行。
- 值加密保存在 Amber 里，不会出现在聊天记录里，agent 也拿不到；只交给声明了它的这条指令，别的指令拿不到。
- 设置后只能覆盖或删除，不能再查看，界面上只显示末尾 4 位。改值不需要重新审核；增加或删除密钥的名字需要提交新版本。
- 脚本如果把密钥原样打印出来，结果里会自动显示成 `***`。
- 指令只有创建人能执行，所以密钥只有创建人自己在用。**全局指令例外**：所有执行人共用同一份密钥，看到的是这个凭证的权限范围，不是执行人本人的权限，结果卡上会标「使用全局指令共用的密钥」。
- 需要密钥的指令，agent 不能直接执行，总要你本人在确认卡上点一下。
- 能防的是其他指令、agent、群里其他人、其他进程读到明文；防不了的是审核时没看出来的恶意代码，所以审核时要留意代码怎么使用密钥。
- 指令下线时，它的密钥一起删除；同名的新版本审核通过后，沿用原来的密钥。
