# 触发器

触发器让 Amber 在某件事发生时主动通知你：发到你的私聊，或者发到你所在的群并 @某个机器人。被 @ 的机器人（比如你的 agent）收到就会接着处理，不用每隔一段时间去查一次。

## 能订阅哪些事

| 事件 | 什么时候 | 谁能订阅 |
|---|---|---|
| 应用提交审核 | 有人认领应用并提交审核 | 审核人、管理员可以订阅所有应用；其他人只能订阅自己的应用 |
| 应用审核通过 | 应用生效 | 同上 |
| 应用被驳回 | 审核没通过，或审批被撤回 | 同上 |
| 应用下线 | 应用被下线 | 同上 |
| 执行失败 | 你执行的应用失败了 | 只能订阅自己的执行 |
| 定时执行有输出 | 你的定时任务运行后有输出（监控类应用平时不输出，有输出就说明有异常） | 只能订阅自己的执行 |
| 定时任务被自动暂停 | 你的定时任务因为连续失败、应用更新等原因被 Amber 暂停 | 自己的定时任务；管理员可以订阅所有 |
| 执行端离线 / 重新上线 | 执行端连不上，或恢复 | 管理员 |
| 页面发布 / 页面调用的应用变化 | 你的页面应用确认发布 | 自己的页面；管理员可以订阅所有 |

订阅时可以只看某一个应用（应用事件、执行事件、定时任务事件）。全局应用也一样：只看它的时候，不管它在哪个群、谁的私聊里执行或建了定时任务，都算（「执行失败」「定时任务被暂停」这类事件按应用本身认，不按在哪里执行）。比如管理员可以建一个「定时任务被暂停，只看某个全局应用」的触发器，覆盖所有人用这个应用建的定时任务。

**能不能收到，每次发通知时都会重新检查**：不再是审核人了，就收不到所有应用的审核通知；退出了通知要发去的群，触发器会自动暂停。

## 通知里有什么

只有发生了什么：哪个应用、在哪个群、谁、什么时间，以及失败原因这类简短说明。**不包含执行结果**，因为结果是按执行人的权限查出来的。

通知最后有一行给 agent 读的编号，比如：

```text
amber-event app.review_started event=42 command=9bba8b5d spec=075b025f
```

agent 收到后可以凭这些编号去查应用、运行记录等。

## 怎么建

**在网站上**：左侧「我的触发器 → 新建触发器」，选什么时候、哪个应用、通知到哪里（我的私聊，或者你所在并且 Amber 也在的群），发到群里时可以勾选同时 @哪些机器人。建好立即生效。

**让 agent 建**：比如对 agent 说「有应用提交审核时，在这个话题里通知 Beta」。agent 运行 `amber trigger add`，群里出一张确认卡片，你点「确认」后生效，见 [agent 接入](cli-and-skill.md#触发器)。

每人最多 20 个触发器。

## 管理

在网站「我的触发器」里选中一个，可以看到最近触发的记录（已发送、未发送及原因、发送失败），也可以暂停、恢复、删除。agent 只能暂停，恢复和删除要在网站上做。管理员在「系统管理 → 所有人的触发器」里能看到并管理所有人的触发器。

## 防止刷屏和丢失

- 一个触发器每分钟最多发 10 次、每天最多 200 次。超过就自动暂停，并私聊通知你，在网站上可以恢复
- 事件先记下来再发通知，Amber 重启也不会丢；发送失败会在 30 秒、2 分钟、10 分钟后重试，仍然失败就记为发送失败
- 同一件事对同一个触发器只发一次
- 建、确认、暂停、恢复、删除和发送失败都写审计日志（类别「触发器」）
