# Amber

**AI 跑通的，Amber 封存。**（Freeze what works.）

跑通一次，随时再用。

Amber 把「和 LLM agent 一起跑通的一次操作」封存成经过审核的确定性应用，在飞书里一键执行。执行时不经过模型。

**定位：AI 当驻场工程师，Amber 负责交付。** 对不写代码的同事来说，AI 助手就像身边的驻场工程师（FDE）：听需求、写脚本、把事情跑通。Amber 负责把它做出来的东西交付成团队能长期依赖的工具：审核把关、锁定版本、以真实身份执行、人人一键可用、按时自动运行，需要时改版或下线。

## 为什么叫 Amber

Amber 是**琥珀**。琥珀把一瞬间的东西封存起来，过很多年取出来还是原样。Amber 做的是同一件事：把和 AI 一起跑通的那一次操作封存起来，以后每次执行都和审核通过时一模一样，不会因为模型换了想法而变。

- **封存**：审核通过后代码按哈希锁定，改一个字都要重新审核。
- **一次成形，长期保存**：Run it once. Keep it forever.（跑通一次，随时再用）
- **Logo**：一滴琥珀里封着一条斜杠「/」，代表一个被封存的应用。

## 工作流程

1. **提交**：agent 提交一份草稿，包含参数和一段 Python 脚本。草稿里的任何内容都不被信任。
2. **认领**：Amber 在应用所属的群或私聊里发出认领卡。认领人以**自己的身份**（来自飞书事件，而不是 agent）试运行一次，确认后提交审核。
3. **审核**：Amber 把完整代码写进飞书知识库文档，并发起飞书审批；**所有审核人都同意**才生效。通过的版本按哈希锁定，代码一改就要重新审核。
4. **执行**：人跟自己的 agent 说话，agent 用 `amber` 命令行调用。不需要身份的应用直接执行、结果交给 agent；需要身份的，Amber 在会话里发一张确认卡片，**谁点就以谁的身份执行**。也可以直接在群里（或私聊里）`@Amber` 用卡片表单执行。
5. **改版与下线**：同名提交即新版本，认领卡和审核文档附代码差异，只有原创建人或管理员能认领，审核通过后自动替换；挂在旧版本上的定时任务暂停，创建人确认后换绑。创建人或管理员可以下线应用（飞书里会再确认一次）。
6. **定时**：审核时允许定时的应用（新草稿默认允许），可以在网站上创建，或由 agent 发起、人在卡片上确认，以创建人的身份运行；脚本没有输出时不发消息，适合做监控。创建人退群时任务暂停并私聊通知（成员名单缓存 10 分钟，退群后最长约 10 分钟才会暂停）。

## 设计原则

- **只有「应用」一个概念**：应用 = 参数 + 一段脚本，代码就写在应用里，没有执行器、渲染器、步骤这些概念。
  - `script`（脚本）：所有应用都在 macOS 沙盒里运行。系统目录和常见语言工具链（Homebrew、nvm、pyenv 等）可读，所以外部依赖能用；**应用自己不写路径**，能访问哪些数据由它选的**运行环境**决定（在执行端上登记、管理员批准，可以直接从 botmux 机器人导出，和那个机器人能访问的完全一样）。不选环境就只能读写本次运行的临时目录。Amber 和执行端的密钥、~/.ssh、钥匙串任何环境都打不开。声明了才能联网。可以用 `script.interpreter` 指定带第三方包的 Python。规则模型移植自 botmux 的 FsPolicy。见[执行端](docs/executor.md)。
- **输出只是内容**：脚本输出 Markdown；其中的 ` ```vega-lite ` 和 ` ```table ` 代码块由各渠道自己适配（飞书卡片转成原生图表和表格，网页可以完整显示同一份内容）。
- **不区分读写**：脚本会不会改数据由沙盒、审核人和服务方的权限共同把关。应用只有两个选项，随代码一起审核：`confirm`（执行前需要在表单上确认）和 `schedulable`（允许定时执行）。认领时一律试运行，试运行就是真实执行一次。
- **作用域**：应用属于创建它的群或私聊；管理员可以把它设为全局可用。
- **应用密钥**：像生产部署的环境变量。应用声明需要的密钥名字（随代码审核），值由创建人或管理员在私聊或网站上填写，AES-256-GCM 加密保存；运行时只把声明过的密钥经标准输入交给这个应用，输出里出现的密钥原文自动遮成 `***`。agent 拿不到值，需要密钥的应用总要人点确认才执行。
- **执行身份凭证**：脚本声明要调用的服务时，Amber 为本次执行签发短时效的 Ed25519 签名凭证（`iss amber`、`aud`、`sub` = 执行人 union_id、应用、版本哈希、执行编号、第几次调用、过期时间）。脚本声明每次执行最多调用几次，就拿到几张凭证，每张只能用一次。服务方用 `node src/cli.ts keys` 从私钥文件导出的公钥验证（固定写进服务配置，运行时不访问 Amber 端口）。声明了服务的脚本不能访问外网。

## Roadmap

按优先级（详见 [ROADMAP.md](ROADMAP.md)，总览 [#5](https://github.com/xu4wang/amber/issues/5)）：

1. **在数据所在的机器上执行**（[#6](https://github.com/xu4wang/amber/issues/6)）：Amber 执行端 + 运行环境。环境定义能访问的数据（可从 botmux 机器人导出），管理员批准；应用只选环境，能访问机器人在本机建立的数据（如台账）
2. **在结果里 @ 人或机器人**（[#1](https://github.com/xu4wang/amber/issues/1)，已完成）：脚本输出 `@名字`，把结果交给本群的另一个机器人或某个人继续处理
3. **验收：GitLab 仓库检查**（[#2](https://github.com/xu4wang/amber/issues/2)）
4. **配置项**（[#3](https://github.com/xu4wang/amber/issues/3)，已完成）：在网站上设置一次、以后每次执行自动带上的参数
5. **Amber Store**（[#4](https://github.com/xu4wang/amber/issues/4)，已完成）：审核过一次的应用，各群各装一份、各配各的；安装不需要审批，升级自己决定

最近完成：应用密钥（像生产部署的环境变量）、文档站与视频手册。
